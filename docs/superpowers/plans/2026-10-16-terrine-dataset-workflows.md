# Terrine Dataset Workflows Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. This document amends the linked tasks; it does not authorize package implementation.

**Goal:** Make existing dataset construction useful for batch training, scoring and longitudinal state analysis, with bounded operational feedback for people and agents.

**Architecture:** Reuse the native Catalog, Design/Frame compiler, shared metadata and customer-owned runtime. Convenience views are projections and re-anchoring, not another compiler. Monitoring observes execution; it never becomes an execution authority.

**Tech Stack:** The master plan's Python/Ibis/Arrow/DuckDB stack. Existing R/Python modeling tools consume exported data. OpenTelemetry is an optional integration, not a core dependency or required service.

**Spec:** [Datasets-only scope decision](../specs/2026-10-18-terrine-scope-datasets-only.md), plus the [master dataset plan](2026-10-16-terrine-build.md). State-panel, training/scoring and operational workflows produce datasets only.

**Current scope:** [Datasets-only scope decision](../specs/2026-10-18-terrine-scope-datasets-only.md) supersedes any estimation or causal-analysis implication in the historical roadmap. Training/scoring and operational workflows produce datasets only; downstream analysis is outside terrine.

## Global constraints

- No increment edits; no MOST estimator, online feature store, training framework, bitemporal storage system, hosted telemetry service or second scheduler.
- Preserve exact timestamps, half-open windows, declared completeness, numeric certificates, snapshot verification and narrow stable refusals.
- Explicitly requested bounded unit-period output is allowed. Hidden dense temporal intermediates and anchor-by-all-events fanout are not.
- Shared feature definitions prevent duplicated logic, not all historical-availability or training/scoring skew. Effective-time reconstruction remains labeled retrospective.
- Customer rows, SQL, credentials and model-training payloads never enter monitoring. No outbound collection by default.
- All checks below are future implementation requirements, not claims of passing package tests.

## Review focus

1. Label windows cross a split cutoff or source readiness changes: retain exact unavailable reasons and prevent assignment to an invalid evaluation split.
2. A scoring request inherits event-cohort selection or future labels: reconstruct an explicitly selected roster-based feature-only design before validating required sources.
3. A missing state observation is mistaken for inactivity or bridged to a later observation: retain scheduled rows, gaps and independent completeness.
4. Cancellation races publication or a worker disappears: distinguish a request, stale knowledge and durable completion.
5. An observer drops events or exports secrets: bounded monitoring cannot change execution truth, and payloads use an allowlisted schema.

## Task 6.2: bounded state-panel datasets

**Depends:** 4.2 only, not estimators, survival or event sequences. **Files:** `spec/state_panel.py`, `compile/shapes/state_panel.py`, `tests/spec/test_state_panel.py`, `tests/compile/test_state_panel.py`, `examples/state_panel.py`; extend existing shape dispatch, safe serialization, shared metadata and guide/changelog. No source-property mode, separate Catalog registry or generic CASE/lag expression system is needed.

### Interfaces and state sources

Add frozen, data-only constructors:

```text
StateObservations(property: str, *, levels: tuple[str, ...],
                  ordered: bool = True, absorbing: tuple[str, ...] = ())
BinnedMetricState(metric: str, *, cutpoints: tuple[int | float | Decimal, ...],
                  levels: tuple[str, ...])
StatePanel(state: StateObservations | BinnedMetricState, *,
           max_periods: int, baseline_features: Mapping[str, Expr] | None = None)
```

At this milestone extend `Design.shape` from `"cross_section"` to `"cross_section" | StatePanel`; keep one existing shape dispatcher. Require a roster-backed finite Schedule, positive step, exact whole number of periods and positive max_periods. Origins are start-inclusive/end-exclusive; the final outcome endpoint is end. Reject an over-cap/partial-final-period schedule statically. Ordinary `Design.features` and eligibility remain per-origin; baseline_features are computed once per unit relative to Schedule.start and broadcast. Common baseline never shifts to the first retained row or delayed entry. Nonempty Design.outcomes and non-null Design.treatment refuse for this shape: the response is to_state; an intervention assignment may be an explicit baseline feature without a causal claim. Existing build/validate/preview/materialize APIs remain the entry points.

**Observed states:** resolve a source-owned string property with dimension=None and as_of=event_time. `StateObservations` explicitly interprets the value at Source.timestamp as a point observation; it does not invoke SCD2/asof carry-forward. Levels are at least two unique nonempty strings, null is not a level, and absorbing is a duplicate-free subset in declared order. Ordered means ranked, not equally spaced or automatically good/bad. Reuse source entity mappings, readiness and snapshot closure. Customers may bind an existing dbt observation table; no new physical input format is required.

**Binned period states:** reuse the named metric's ordinary aggregation and semantics. For step delta and origin s, prior state summarizes `[s-delta,s)` and response summarizes `[s,s+delta)`. Cutpoints must be finite and strictly increasing with one more distinct string level than cuts; reject bools, numerically equal cuts and lossy/unsupported threshold coercions. Bins are `(-inf,c0]`, `(c0,c1]`, ..., `(cn,inf)`. Preserve exact integer/decimal threshold meaning and canonical scalar encoding; no unchecked float cast. A certified interval belongs to a bin only when the entire interval lies inside it; a singleton equal to a cut belongs to the lower bin. An otherwise valid certificate spanning a cut produces null with `ambiguous_state_bin`, never a guessed state. A failed numeric certificate still raises its existing refusal; do not hide it as missingness. Complete empty additive zero is classified normally; incomplete/all-null/undefined aggregates retain their reasons. This source is ordered and has no absorbing states.

Cutpoint serialization preserves declared order and exact representation: integers are tagged canonical decimal strings; Decimals are tagged sign/digit-tuple/exponent triples; finite Float64 values are tagged `float.hex()` strings. Loaders reject extra/unknown tags and nonfinite values. Numeric-equal cuts are duplicates even across tags; otherwise the typed encodings may have distinct definition hashes, never silently round to one another. At least one cut and two nonempty levels are required.

BinnedMetricState requires a numeric, non-boolean metric result. Refuse boolean/categorical results with the route to an appropriate count/numeric metric or declared state observations; do not invent a numeric coding.

Compile each completed period's value/certificate/state once into a logical state relation, reused as one transition's response and its successor's prior. This prevents adjacent sides disagreeing through independent aggregation orders. Existing metric.window_days and calendar-average alignment restrictions still apply. No transformation silently rewrites the metric's meaning.

### Pairing, missingness and terminal behavior

For each scheduled origin s and endpoint e=s+delta, observed-state rows use the exact observations at s and e. Keep unchanged states. A missing point stays missing on both adjacent uses; never bridge to the next available observation, interpolate or infer inactivity. Point usability requires `coverage.start <= t < coverage.end_exclusive` and the same independent half-open unit observation bounds. A point at the exclusive end is unavailable even though an aggregate ending there may be complete. Missing readiness refuses; other state reasons distinguish incomplete_coverage, incomplete_observation, missing_state_observation and state_value_null. A known-null observation can be measured/completely observed but is not a usable label.

For observed states, find the first usable absorbing observation from declared history through the panel endpoint before AnchorRange/eligibility filtering. If it is at or before an origin, emit no outgoing row. If it falls in `(s,e]`, emit exactly one incoming transition ending at that actual timestamp, even if the prior state is missing; then suppress the later suffix. An off-grid absorbing observation is allowed; other off-grid observations in the requested panel interval refuse with a route to supplying aligned assessments. Never fabricate a pre-start transition or post-terminal self-stays. Repeated identical terminal padding is redundant; a later usable different state refuses. Source/unit measurement bounds have no terminal-boundary exception. Membership exit controls origins, not independently observed terminal outcomes.

For binned states, endpoint is always e, gap is delta and terminal is false. Missing/ambiguous periods remain missing; no absorption, persistence or terminal shortening is inferred. State assembly includes the preceding period needed for the first prior state, not an unbounded historical spine. All variants apply existing feature/eligibility cutoffs relative to their declared baseline/origin, never the future terminal endpoint. Existing eligibility cannot select on response availability; missing states alone do not cause eligibility refusal.

### Output and shared metadata

Keep `(unit, anchor_id)` identity, UTC `t0 == from_time`, original Int64 period_index, UTC from_time/to_time/scheduled_to, exact Arrow-duration gap, nullable string from_state/to_state, boolean terminal, named covariates and their metadata columns. Preserve original indices after filtering. Reserve shape columns through the existing namespace rules.

Task 6.2 coordinates these additions to the shared contract owner: `Roles.prior_state: str | None = None`; `FeatureCutoff.reference: Literal["row_t0","panel_start"] = "row_t0"`; and `Provenance.state_panel: StatePanelMeta | None = None`. `StatePanelMeta` records the serialized state-source definition, levels/order/absorbing set, panel_start, administrative_end, period_seconds, baseline/time-varying feature names, structural prior-state timing (`strict_period`/`at_origin`), and references to the period/time/gap/terminal columns. Set prior_state=from_state, outcomes=(to_state,), cluster_unit=unit, treatment=None; ordinary covariate features exclude the structural prior state. No estimator may mistake this repeated-measures shape for independent cross-sectional observations.

Both states retain independent ColumnMeta completeness/reason references. Observed states have window=None plus point-column references in StatePanelMeta, not zero-width Windows. Binned states retain the respective prior/response Window and measurement provenance; ambiguous categories are incomplete while any exposed underlying aggregate preserves its own measurement status/certificate. Observation at origin is a structural conditioning value, not a strictly pre-origin feature. Binned prior state is strictly pre-origin. Preserve actual knowledge policy; event/effective time alone does not prove recorded-at availability.

Arrow/Parquet/warehouse manifests preserve ordered levels as explicit metadata, never lexical/dictionary-code order. R/Python consumers construct categorical targets explicitly. Future terminal flags, realized endpoint/gap and label availability are never automatically selected as forecasting predictors; scheduled horizon remains available. Ordinal/Markov/proportional-odds assumptions and causal identification belong to the external analysis, not this builder.

## Task 7.2 amendment: training views and scoring snapshots

**Depends:** existing 7.2 prerequisites, not any estimator or trainer. **Files:** `spec/dataset.py`, `dataset/{training,splits,manifest}.py`, existing Design/Frame facades, shared `data.py` metadata, `examples/{ml_staging,batch_scoring}.py`, `tests/dataset/{test_training_view,test_scoring_snapshot,test_splits}.py`. Keep the master's staging/streaming/publication/refresh interfaces; this amendment owns the new convenience APIs and view metadata.

### Interfaces and meaning

- `Frame.training_set(*, label: str | tuple[str, ...], features: tuple[str, ...] | None = None, incomplete_labels: Literal["drop", "keep"] = "drop", split: TimeSplit | GroupSplit | None = None) -> Frame` returns a new lazy view; it never mutates the original Frame or executes a query. Labels select existing named outcomes; a string normalizes to a one-element tuple. Reject empty/duplicate/unknown selections. Default features are the existing ordinary feature roles; an explicit subset can additionally select a declared structural prior-state role from Task 6.2. Outcomes, treatment, realized future times/gaps and other metadata cannot silently become features. Preserve unit/anchor/time identity and all metadata/certificate columns required by the selected values. Unselected outcomes and treatment are omitted from the view; no label renaming or second semantic definition.
- `Design.snapshot(model: Model, *, as_of: date | datetime | str, eligibility: Mapping[str, Predicate], features: tuple[str, ...] | None = None) -> Frame` builds a lazy scoring view. Accept an ISO date, aware ISO timestamp, date/aware datetime, or the literal `"today"`; reject other relative strings and naive datetimes. The model-bound helper resolves today once to the start of the current Catalog-local day using one UTC clock reading. Store the resolved UTC instant in the derived recipe and manifest, never a moving placeholder. Date bounds use the same fixed Catalog day boundary as FixedDate. The feature subset defaults to all original features and uses the same name/AST definitions and gap.
- Snapshot applies only to a cross-sectional Design. Construct a new `FixedDate` Design with the same unit/features/gap, explicit scoring eligibility, no `anchor_range`, no outcomes and no treatment. Require that unit's configured roster; neither historical event anchors nor recent activity define the scoring population. The required eligibility argument prevents accidental reuse of a training-only cohort; callers may deliberately pass the original predicates. Reject unsupported shape requests narrowly with the route to constructing an explicit scoring Design.
- Prune unused expressions before required-source/readiness validation and query construction. No future label readiness or outcome calculation is required for scoring. Existing whole-model immutable-binding verification remains a stronger safety check if the caller supplied such a binding; this helper does not weaken or forge it. Missing selected-source coverage refuses; insufficient selected coverage follows ordinary null/reason semantics. Never silently shift as_of to the most recently complete source date.
- Task 4.2 moves readiness requirements from eager all-metric Model construction to the selected Design boundary. Acceptance constructs Model from the original feature-and-label Catalog with feature-source coverage only, then successfully builds a scoring snapshot without label readiness; selecting an uncovered label still refuses. Keep complete verification of any supplied immutable binding.
- `incomplete_labels="drop"` removes rows with any unavailable selected label, including a known-null label, and records excluded counts by exact reason. `"keep"` retains their null values/reasons. Do not rewrite completeness for known-null values or impute false/zero. Neither policy is a correction for informative censoring; survival event/censor fields remain distinct data, not an instruction to discard all censored subjects.
- `tr.time_split(*, train_until: date | datetime | str, validation_until: date | datetime | str | None = None, embargo: str = "0d", groups: GroupSplit | None = None) -> TimeSplit` is a pure, serializable policy. Only explicit ISO boundaries are accepted; no today token. Normalize dates at model binding and retain the bound instants. Boundaries are ordered; embargo is nonnegative elapsed time.
- `tr.group_split(*, group: str = "unit", train_fraction: float = 0.8, validation_fraction: float = 0.1, seed: int = 0) -> GroupSplit` uses a unit/declared cluster identity, not outcomes, treatment or availability. Reject bool/nonfinite fractions; require `0 < train_fraction < 1`, nonnegative validation share and sum <= 1. The remainder is test, possibly zero for a two-way split. Version the typed-key hashing codec and thresholds; persisted policies retain exact normalized fractions and seed. Support string/integer keys initially; unsupported key encodings refuse rather than stringify ambiguously. Duplicate appearances of a key always receive the same bucket.

For time splitting, train origins are before train_until; validation starts at train_until + embargo and ends before validation_until when supplied; test starts at validation_until + embargo. Without validation_until there is validation but no test. A selected label must be usable and its full window must end at or before the next split boundary to enter the earlier split. Purge overlapping horizons, including between validation/test. Group-disjoint evaluation is optional: future behavior of existing users may reuse units across time; unseen-unit evaluation additionally intersects the corresponding deterministic group bucket with the time bucket. Never reassign mismatches to recover sample sizes. Retained incomplete, purged or mismatched rows receive the reserved split value `unassigned`, not a usable training/validation/test assignment; record counts/reasons. Incomplete-label drop still removes unavailable-label rows. Downstream training consumes only assigned training rows and fits preprocessing there, not on the full view.

Point-state labels are distinct from half-open aggregate labels: an observed `to_state` is available before a split boundary only when its exact to_time is strictly earlier. A binned period label may end exactly at the boundary because it excludes the endpoint. Use the shape's explicit source/support metadata; do not invent a zero-width Window or apply an interval `<=` rule to a point. Include boundary-equality checks for both label kinds.

The group codec is canonical UTF-8 JSON `["terrine.group.v1", seed_as_decimal_string, key_type, key_value]`, with compact separators, no Unicode normalization of values, key_type `str` or `int`, and integer keys encoded as canonical decimal strings. Reject bools/nulls/unsupported keys; seed is a nonnegative signed-Int64 integer, never bool. SHA-256 interpreted as an unsigned big-endian integer h selects train if `h < floor(p_train * 2**256)`, validation if it is below `floor((p_train + p_validation) * 2**256)`, and test otherwise. Convert each fraction via its decimal string and compute boundaries with exact integer/rational arithmetic, not floating multiplication or a finite-precision Decimal context. Collection order and input row order do not affect assignment. The group key is audit/split metadata, not automatically a feature. A backend advertises group splitting only after its encoding/hash/threshold implementation matches reference vectors exactly.

Add a pure frozen `DatasetViewMeta` in `data.py` and optional `Provenance.dataset_view = None`. Its fields are kind (`training`/`scoring`), selected feature/label name tuples, canonical `view_hash`, `feature_definition_hash`, resolved_as_of (UTC or null), incomplete-label policy (or null), serialized split policy (or null), and exclusion/assignment counts by reason (unknown until execution). These metadata are retained in MaterializedFrame, Arrow metadata and Dataset/export manifests. View hashing includes the parent recipe, selections/policies and resolved instants, not runtime counts; generation/cache identity includes the view hash. Feature-definition hashing includes selected expressions and referenced semantic definitions, unit, temporal boundary/gap and knowledge policy, but excludes labels, anchors/population and source generations. It supports semantic parity checks, not a claim of identical source data or full reproducibility.

Surface per-feature recorded-at versus retrospective knowledge and source generations in preview/manifest. A safe temporal split is not proof that late-arriving or retrospectively corrected features were known at historical prediction time. Do not claim point-in-time historical availability without the source construction supporting it; no bitemporal implementation is introduced here. Preserve original ordinal/shape metadata when a training view selects a structural prior state; its availability at origin is not relabeled strictly pre-origin or causally safe.

### Durable reconstruction recipe

Task 7.2 owns `DatasetRecipe(schema_version=1, base_design, view=None)` in `spec/dataset.py`. Base_design is the complete canonical data-only Design, including anchors/range, state shape, eligibility, named expressions and gap. View is a tagged training specification (normalized label/features, incomplete policy, split specification) or scoring specification (resolved aware as_of, explicit eligibility and selected features). Reject unknown tags/fields and executable/runtime values. No SQL, credentials, connection handles or VerifiedInputBinding is embedded. A view on an already derived view refuses with a route to the original Design/Frame rather than ambiguously composing filters.

Every staged manifest includes this recipe and its canonical hash, or an immutable customer-owned recipe reference plus digest/schema version. Atomic publication verifies both recipe and output; retention/pins protect referenced recipe objects just like data shards. `Dataset.from_manifest(manifest: DatasetManifest, *, con) -> Dataset` validates version, digest, ownership and pinned output identity; recipe references resolve only through owner-configured storage, never arbitrary URLs. It returns a lightweight reference, not collected rows. Missing/corrupt/unsupported recipes use `terrine.dataset.invalid_recipe` owned by `spec/dataset.py`, before any source-data work.

`plan_refresh`/`refresh` reconstruct the same Design/view recipe with the explicitly supplied Model. Revalidate semantic references, current snapshots/readiness and budgets; model-definition changes are visible in the refresh plan and force the existing new-version/rebuild rules, never reinterpret cached partitions silently. Static predicates/anchors/view choices are not recoverable from a hash or Model alone. Refresh preserves resolved scoring as_of and split boundaries; a later scoring date requires a new explicit snapshot recipe. Default agent/telemetry responses expose safe recipe references/hashes, not recipe literals, which can themselves contain sensitive owner-supplied values.

## Tasks 7.1 / 12.1 amendment: live operational feedback

**Ownership:** 7.1 owns `runtime/{status,events}.py`, customer-owned state/CLI operations and optional `adapters/opentelemetry.py`; 7.2 attaches pinned dataset/export references; 9.1 preserves scheduler/runtime state parity; 12.1 exposes the same operations under agent policy. No new runtime/scheduler subsystem or standalone service.

### Execution truth and small control surface

- Add Python runtime operations `get_run(run_id, *, con, namespace) -> RunStatus`, `read_run_events(run_id, *, con, namespace, after=None, limit=100) -> EventPage`, and `cancel_run(run_id, *, con, namespace) -> CancelReceipt`; con/namespace are explicit trusted runtime context, not ambient globals or agent-supplied credentials. CLI equivalents are `terrine status RUN_ID --json`, `terrine events RUN_ID --after CURSOR --limit N --json` and `terrine cancel RUN_ID --json`; namespace/connection come from owner configuration. Agent tools receive run IDs/cursors only and use owner-bound context.
- Allocate/persist a run ID and request-key binding before expensive work, and expose it in the initial CLI event/agent acceptance response. Existing request-key replay returns the same run/result; a changed request under that key refuses. Ordinary Python/CLI execution may remain synchronous. An asynchronous agent start must use an explicitly owner-provided executor and return accepted, not completed; absent an executor it cannot pretend to launch durable background work. There is no implicit detached process or hosted runner. Execution remains callable by the existing CLI/orchestrator.
- `RunStatus` fields: run_id, durable_state, state_version, updated_at, heartbeat_at, lease_expires_at, freshness (`current`/`stale`/`unknown`), phase, bounded progress/cost/readiness summaries, safe error_code, pinned result_ref, and latest_event_cursor. Times are UTC; absent measurements remain null. A stale heartbeat means owner liveness is unknown, not successful execution or proven query termination. Heartbeats do not prove forward progress.
- Durable states are `queued`, `running`, `cancel_requested`, `succeeded`, `failed`, `cancelled`. Queued can enter running or be cancelled before work; running can fail, request cancellation or succeed. Cancellation-requested remains active until acknowledged/reconciled. Durable terminal states do not regress. Lease loss changes freshness and triggers existing fenced recovery; it does not manufacture a terminal state. If status cannot be read authoritatively, return a typed unavailable result, not a fabricated queued/failed state.
- `CancelReceipt` contains run_id and disposition (`requested`, `already_requested`, `already_terminal`), plus the observed RunStatus. Acknowledged cancelled means work stopped before publication; a request alone does not prove backend work/billing stopped. Serialize cancellation and publication decisions through the same fence/compare-and-publish protocol. If publication commits first, status is succeeded with its pinned result; accepted cancellation cannot retroactively unpublish it. If cancellation wins before publication, no visible new generation is published. Ambiguous external effects remain stale/unknown until reconciliation; never return both cancelled and a successful publication. Crash after publication is reconciled from the authoritative manifest, not a missing success log.

### Bounded events, honest measurements and privacy

`RunEvent` has run_id, per-run monotone sequence, UTC at, kind and a bounded typed payload. Durably record lifecycle decisions with runtime state; progress updates may be sampled/coalesced. `EventPage` has events, next_cursor, has_more and cursor_gap. Cursor encodes the run/sequence opaquely; after is exclusive and run-bound. Reads cap limit at an owner-configured maximum (default 1000). Retries may duplicate delivery; clients deduplicate by run/sequence. Retention gaps explicitly signal resynchronization via get_run/latest_event_cursor, never silently present a partial history as complete. Retain terminal summaries per owner policy; telemetry retention cannot delete pinned manifests/generations.

Progress reports fixed phases (planning, validating, materializing, exporting, publishing, reconciling, complete), completed work and a known total or null. Coalesce progress at most once per second per run; lifecycle decisions are not dropped. No per-row/per-unit event stream, arbitrary labels or fabricated percent-complete. Cost summaries distinguish estimates, measured actuals, configured limits, enforcement capability and unknown reasons: scan bytes, output rows/bytes, egress and elapsed time are different quantities. Backend measurements missing means unknown, not zero; row limits do not imply scan limits. Readiness summaries use declared coverage and aggregate null reasons, never maximum event time or unit-level payloads.

Status/events require run-scoped read permission; cancellation requires its own permission. Run IDs/cursors/trace context do not confer authority. Use allowlisted structured fields and existing stable refusal codes; no rows, raw SQL, customer keys, connection strings, credentials, prompt content or raw backend exception text. Unknown executor error details stay in owner-controlled diagnostics, not public events. Telemetry content is untrusted descriptive data, never an instruction to widen budgets, retry, execute SQL or modify a plan.

Status/event reads inspect only the runtime store; they do not launch dataset scans, counts, readiness probes or new backend cost queries. Execution records measurements it already obtained. Polling/backoff and event retention are owner-configured and bounded; observability must not turn a cheap metadata check into unbudgeted warehouse work. The optional adapter does not enable database-client auto-instrumentation or query-text capture.

Best-effort monitoring/export failures cannot mask execution errors, block execution indefinitely or decide publication. Required runtime state persistence still fails closed: it is not an optional log sink. Optional OpenTelemetry instrumentation uses the application's configured SDK/exporter/collector, disabled by default with no outbound endpoint. Start with traces and low-cardinality metrics; do not make durable event/cursor semantics depend on OTel logs. The [signal model](https://opentelemetry.io/docs/concepts/signals/) and [Python integration](https://opentelemetry.io/docs/languages/python/) provide interoperability; verify versions/status at implementation. Run IDs may identify trace context or bounded event records, never unbounded metric-label dimensions. A telemetry backend is not a control plane.
