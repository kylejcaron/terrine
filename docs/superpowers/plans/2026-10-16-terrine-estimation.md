# terrine Simulation and Estimation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build an independent potential-outcome oracle and native, honestly cross-fitted baseline-treatment ATE estimators whose recovery, uncertainty, weighting, and refusals are tested independently of the dataset compiler.

**Architecture:** A NumPy/Arrow simulator generates potential outcomes before generating observed events; its truth module never calls the production compiler. Native IPW, AIPW, and regression adjustment consume only `terrine.data.MaterializedFrame`; overlap and balance consume data/results rather than estimator implementations. Fixed-cohort estimation is a complete vertical slice, not an approximation to sequential-trial or grace-period initiation inference.

**Tech Stack:** Python `>=3.12,<3.15`; frozen pydantic v2 configuration/result models; NumPy; SciPy optimization, linear algebra, and log-tail functions; PyArrow; pytest with slow/parameter-recovery markers; DuckDB/ibis only in integration tests. Native dependency admission, including `scipy.special.ndtri_exp`, belongs to master Task 0.1; the optional increment adapter is not a numerical or integration prerequisite.

**Spec:** `docs/superpowers/specs/2026-10-16-terrine-handoff.md`, especially §§12, 17–19, as corrected by the concrete contracts below and the master `docs/superpowers/plans/2026-10-16-terrine-build.md`. The handoff's mandatory increment dependency, grace-period horizon-shift repair, and equality requirement for inequivalent adapters are superseded here. Ground truth is independent of production compilation.

## Review Focus

1. A future-initiation indicator can remain selected on survival/adherence after moving the outcome start. Task 4.3 must refuse that causal request; Task 4.4 must still build its descriptive dataset.
2. Categories and preprocessing learned from held-out rows break honest cross-fitting. Task 4.3 tests unseen held-out levels, arm-specific missing levels, and preprocessing isolation separately from ordinary prediction accuracy.
3. The variance of fitted IPW or regression adjustment is not generally the variance of their final row scores; even AIPW needs care under one-sided nuisance misspecification. Task 4.3 includes fitted nuisance estimating equations in its sandwich; Task 4.4 calibrates each method against population rather than realized-cohort truth.
4. Target-population weights and treatment-dependent sampling/design weights have different identification and variance contracts. Task 4.3 tests scale invariance and refuses the latter; Task 4.4 calibrates only the supported fixed baseline target weights.

Task 4.4 checks these producer refusals/nulls at the causal consumer boundary; Task 4.3 checks every declared eligibility cutoff and selected outcome's completeness before fitting.

### Public estimator and nuisance APIs

Expose `aipw`, `ipw`, and `regression_adjustment` from `terrine.estimate` with the same signature:

`(frame: MaterializedFrame, *, outcome: str | None = None, estimand: Literal['ATE'] = 'ATE', folds: int = 5, seed: int = 0, alpha: float = 0.05, nuisance: NuisanceSpec | None = None, diagnostics: DiagnosticPolicy | None = None) -> Estimate`.

Omitting `outcome` selects the sole outcome; zero or multiple outcomes require an explicit valid name. A runtime request for ATT gets `terrine.estimate.unsupported_estimand`, not pydantic coercion or an ATE with an ATT label. `LinearTerms(features: tuple[str,...] | None = None, squares: tuple[str,...] = (), interactions: tuple[tuple[str,str],...] = ())` and `NuisanceSpec(propensity: LinearTerms = LinearTerms(), outcome: LinearTerms = LinearTerms())` are frozen pydantic models in `terrine/estimate/nuisance.py`. `None` selects all baseline feature main effects; include an intercept in every model. Squares/interactions accept numeric features only, with deduplicated canonical term names and explicit refusal of unknown/invalid terms. They are small native linear predictor specifications, not a new general ML framework. IPW needs a propensity nuisance; regression adjustment fits outcome nuisances plus propensity for overlap evidence; AIPW fits both. No synthetic oracle values can enter these default APIs.

`crossfit(frame: MaterializedFrame, *, outcome: str, method: Literal['ipw','aipw','regression_adjustment'], folds: int, seed: int, nuisance: NuisanceSpec) -> CrossFitPredictions` is internal to estimation. `CrossFitPredictions` retains one held-out prediction per row (`log_e`, `log1m_e`, and required `mu0`/`mu1`), fold IDs, and fold-fit score/Jacobian information needed for uncertainty. Each public estimator validates metadata and data before calling it. Use one shared preparation implementation rather than three independent null/weight validators.

### Estimands, formulae, and identification

Let independent units be `i=1,...,n`; baseline features `X`, baseline treatment `A in {0,1}`, observed complete-horizon outcome `Y = A Y(1) + (1-A)Y(0)`, and known positive target weight `q(X)` (`q=1` when absent). The target is the superpopulation weighted ATE

`tau_q = E[q(X){Y(1)-Y(0)}] / E[q(X)]`.

It requires consistency/well-defined treatment, no interference between independent units, baseline conditional exchangeability, positivity on the target support, correct temporal construction, and complete follow-up. Features must not be treatment descendants merely because they happen to be recorded before the outcome. Metadata and diagnostics do not establish these causal assumptions. Native IPW additionally requires a correctly specified propensity model, regression adjustment a correctly specified outcome model, and AIPW at least one of those model families to be correctly specified for consistency. The sandwich requires finite second moments of the weighted scores, a nonsingular population Jacobian and regular fixed-dimensional nuisance fits with fixed finite fold count; observed finite values alone do not prove these population conditions. Finite-sample unbiasedness or finite-sample normality is not promised.

For held-out predictions `e_i = P(A=1|X_i)`, `m_ai = E[Y|A=a,X_i]`, and `Q=sum_i q_i`, compute:

- **IPW (target-normalized Horvitz–Thompson, not arm-normalized Hájek):** `tau_hat = sum q_i [A_i Y_i/e_i - (1-A_i)Y_i/(1-e_i)] / Q`.
- **Regression adjustment:** `tau_hat = sum q_i (m_1i - m_0i) / Q`, with separate arm-specific outcome regressions so heterogeneous effects are not silently prohibited.
- **AIPW:** `tau_hat = sum q_i [m_1i-m_0i + A_i(Y_i-m_1i)/e_i - (1-A_i)(Y_i-m_0i)/(1-e_i)] / Q`.

There is no ATT implementation in this task: its target distribution, score, normalization, diagnostics, and variance must be derived separately. Nor is a repeated-row ATE created by changing `n_clusters`: the later panel phase first defines trial weights, risk sets, treatment strategy, and censoring before unit-cluster aggregation becomes meaningful.

A treatment defined by initiation during `[t0,t0+grace)` is selected using future information. Moving outcomes to `[t0+grace,... )` does not remove survival/adherence selection or establish baseline exchangeability. Such frames can be built and described, but these causal APIs refuse them. A later valid landmark analysis must explicitly redefine time zero, eligible risk set, intervention and estimand at the landmark, with its own exchangeability/censoring assumptions; original-time-zero initiation strategies instead need a valid target-trial construction such as clone–censor–weighting. Neither method is implemented under a facade branch here.

### Honest folds, native models, and numerical domain

Canonical fold identity is independent of row order and never Python `hash()`: accept nonnull signed-int64 or UTF-8 string unit IDs; encode with a type tag and length-prefixed bytes, prepend `b'terrine-fold-v1'` and the seed as an unsigned 64-bit big-endian integer, take SHA-256, and reduce its first eight bytes interpreted big-endian modulo `folds`. Pin integer sign encoding and string UTF-8 normalization behavior in tests: preserve exact UTF-8 bytes, perform no Unicode normalization, and encode signed integers as eight-byte big-endian two's complement. Require `2 <= folds <= n`, seed in `[0,2**64)`, no empty held-out fold, and both treatment arms in every training complement. Require residual degrees of freedom for the fits actually performed, rather than inventing arm-specific regression requirements for propensity-only IPW. IDs must be stable baseline identities, not derived from treatment/outcomes. Never retry seeds, stratify after examining outcomes, or leak a unit between train/test. Later repeated rows must share this unit fold, but duplicate units are refused now.

Fit an unpenalized weighted logistic propensity model and separate weighted least-squares outcome models in each training complement, with weights proportional to `q`. Numeric centering/scaling and category vocabularies are learned on that training complement only. Use deterministic reference-level one-hot coding for Boolean/text/dictionary categorical features, selecting levels by typed canonical ordering; a held-out unseen level is `terrine.estimate.unseen_category`, never an all-zero baseline code. A level absent from one training arm can make its outcome design rank deficient; refuse that rank deficiency rather than dropping its column or pooling arms. Null/NaN/infinite features, treatments, outcomes, or weights are refused, as are missing or incomplete outcomes without a supported censoring model. Do not convert a missing categorical value into a legitimate category.

Use `scipy.linalg.lstsq` with a rank-revealing SVD for outcome fitting and `scipy.optimize.minimize(method='trust-exact', jac=..., hess=...)` for the logistic negative log likelihood. Check complete/quasi separation with a linear-program feasibility test (`scipy.optimize.linprog`) before claiming a finite logistic MLE: the signed design has a separating direction if all signed margins can be nonnegative and their sum can be at least one. Every fitted design must have more training rows than columns and full numerical rank; for each arm-specific outcome fit, apply that requirement to that arm's training rows. Check logistic convergence within 200 iterations, scaled mean-loss gradient infinity norm at most `1e-8`, finite predictors/coefficients, and scaled-design/Hessian condition number at most `eps_float64**(-1/2)`. These are explicit numerical acceptance policies, not claims of statistical adequacy. No ridge fallback, pseudoinverse of a rank-deficient system, or fit-on-all-data replacement.

Estimation is float64 numerical analysis, not the compiler's exact integer/decimal arithmetic. Convert required Arrow columns once; check finite casts, refuse integers outside the exact float64 integer domain, and attach decimal/float input-rounding bounds to provenance. For decimal casts, require the original-to-cast error to satisfy the declared policy `abs_error <= 1e-12 + 1e-12*abs(original)` and refuse otherwise, including overflow; tests compare against a Decimal/Fraction reference rather than float-to-float round trips. Do not silently coerce categorical codes into numeric trends. Stable centering/scaling is a reparameterization of the same full-rank linear predictor; preserve it when constructing the uncertainty equations, not a feature-selection operation.

Compute `log_e = -logaddexp(0,-eta)` and `log1m_e = -logaddexp(0,eta)`, use log-sum-exp normalization for diagnostics/weights, and check support before forming large inverse weights. Normalize base weights after scaling by their maximum to avoid overflow; multiplication by any common positive constant leaves estimates, SEs, diagnostics, and ESS unchanged within the declared floating tolerance. Final signed sums and moments use centered/compensated accumulation where appropriate. Every invalid or nonfinite intermediate gets a numerical refusal, not a missing effect, infinity, or a finite fallback.

### Standard errors and diagnostics

Use a **cross-fit parametric estimating-equation sandwich** for all three native methods. For each fold `k`, include its training-only logistic score `q_i 1(F_i != k) x_ik(A_i-e_ik)` when the propensity enters the point estimator, and its arm-specific outcome score `q_i 1(F_i != k)1(A_i=a) z_ik(Y_i-z_ik' theta_ak)` when outcome regression enters it. Add the final target equation `q_i(psi_i-tau)` using the row's held-out fold. These scores are defined for every independent unit and jointly represent overlap between training complements. Fits used only for diagnostics need not add irrelevant nuisance parameters to the point-estimate sandwich.

Write `g_i(eta)` for the concatenated equations, `A = n^-1 sum d g_i/d eta`, and `h_i = -e_tau' A^-1 g_i`. Solve linear systems for the required row of the inverse; do not form an explicit matrix inverse. Compute `se^2 = sum_i(h_i-mean(h))^2 / [n(n-1)]`. Include the cross-fold nuisance derivatives even for AIPW: under one-sided nuisance misspecification, the variance of its final pseudo-outcome alone need not include fitted-model uncertainty. Refuse a singular/ill-conditioned bread, nonfinite influence values, fewer than two independent units, or negative computed variance beyond the declared arithmetic tolerance; do not take an absolute value to hide an invalid variance. Record that this is asymptotic parametric inference with a fixed finite fold count, not a generic black-box-ML or finite-sample guarantee. Later clustered inference can sum unit score contributions before the meat calculation, only after the repeated-trial estimand has been separately defined.

Require finite `0 < alpha < 1`; compute a two-sided normal critical value as `-scipy.special.ndtri_exp(log(alpha)-log(2))`, never from `1-alpha` or an underflowing `alpha/2`. Return checked finite endpoints `value +/- z*se`. Tests compare log-tail round trips at ordinary and extreme representable alpha and refuse invalid alpha; the required SciPy symbol is part of Task 0.1's native dependency compatibility check.

Define `DiagnosticPolicy` in `terrine/results.py` with default lower-tail thresholds `overlap_warn=0.05`, `overlap_fail=0.01`, `max_fail_share=0.01`, `min_arm_ess=20`, `smd_warn=0.10`, and `smd_fail=0.25`, and validate their ordering/ranges. These are configurable screening policies, not identification theorems. `overlap(frame, *, log_propensity, log_complement, policy=None) -> Diagnostic` reports target-weighted arm histograms, ranges, unsupported-tail shares, and each arm's ESS under the actual treatment weights `r_i=q_i/e_i` or `q_i/(1-e_i)`. Tail share above `max_fail_share` outside `[overlap_fail,1-overlap_fail]`, an arm ESS below `min_arm_ess`, or numerical non-support is `fail`; exceeding the warning interval `[overlap_warn,1-overlap_warn]` without a fail is `warn`. Define comparisons through log probabilities; do not subtract a probability to recover its complement.

`balance(frame, *, log_treatment_weights: numpy.ndarray | None = None, policy=None) -> Diagnostic` uses all declared baseline features, with categorical level indicators rather than category codes. Report before/after arm means and absolute SMD. Each arm mean normalizes its own weights; use the fixed pre-treatment target-weighted pooled within-arm SD as the denominator for both before/after SMD, with reliability-weight variance denominator `sum(q)-sum(q*q)/sum(q)`. A constant feature with equal arm means has SMD zero; zero pooled scale with unequal means is a null metric with reason `zero_scale_unequal_means` and `fail`, not infinity or an invented epsilon. The default warning/failure boundaries are `>` the stated SMD thresholds. Always run diagnostics; a failure raises `terrine.estimate.diagnostic_failure` with immutable diagnostic evidence and **no effect value**; warnings attach to an expert estimate. The later agent wrapper must not override hard failures, and may apply stricter policies. Balance/overlap never certify no unmeasured confounding and never silently trigger trimming.
