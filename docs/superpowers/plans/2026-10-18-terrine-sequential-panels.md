# Sequential Trials and Panel Family Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add schedule-based sequential trials, calendar/event panels, and causal methods whose trial-level target, treatment histories, control eligibility, and unit-cluster uncertainty are explicit and testable.

**Architecture:** Extend the existing `Design` and the single shape-dispatch path, retaining `(unit, anchor_id)` rows, `compile_columns`' independent anchor-based value compilation, and the null-safe `(unit, anchor_id)` join. Sequential panels use schedule anchors as trial time zero; `CalendarPanel` canonicalizes to the equivalent `Sequential` design, while `EventPanel` explicitly expands relative periods. Estimation consumes only `MaterializedFrame`, separates descriptive shapes from causal eligibility, groups folds and inference by independent unit, and uses independent pandas-row and simulation references.

**Tech Stack:** Python `>=3.13,<3.15` (provisional per master); Pydantic 2/data-only spec models, Ibis, PyArrow, NumPy/SciPy, pandas only in test/reference extras, pytest/Hypothesis, DuckDB reference backend. No network or live warehouse in unit tests.

**Spec:** [Roadmap Task 5.1](2026-10-16-terrine-build.md#task-51-sequential-trials-and-panel-family), [Estimation and Task 4.4 calibration](2026-10-16-terrine-estimation.md), [Study API](2026-10-16-terrine-study-api.md), [Temporal](2026-10-16-terrine-temporal.md), [Dataset workflows](2026-10-16-terrine-dataset-workflows.md), and [`AGENTS.md`](../../../AGENTS.md) testing/API/refusal/numerical rules. These companion specifications constrain shared contracts; this plan owns Task 5.1 only.

## Global Constraints

- Depend on Task 4.4's validated data/estimation contracts; do not relabel the fixed-cohort ATE or its independent-row inference as a sequential-panel method.
- No increment edits, no network/warehouse in unit tests, no paid resources. Live warehouse checks, if later needed, belong under `integration/warehouse_execution/`.
- Repeated rows retain canonical unit identity, shape-specific `anchor_id`, exact UTC evaluation t0 and parent event/cohort identity, half-open windows, per-column completeness, null reasons, snapshot/provenance, and precision certificates.
- Build on `Model`, `Design`, `Frame`, `MaterializedFrame`, `compile_columns`, `compile_anchors`, the merged `terrine/compile/dispatch.py`, and native execution authority. Values remain compiled independently from anchors and joined null-safely on `(unit, anchor_id)`; do not replace with anchor-by-all-events fanout.
- Task 6.2 StatePanel is merged in `feat/dataset-engine` (`aa40e69`): current `Design.shape` is `"cross_section" | StatePanel`; current `compile_design` dispatches StatePanel then calls `compile_columns`; validation is `_validate_shape`; Frame materializes by recompiling the stored Design and currently writes StatePanel-only metadata. Add all new shapes to these existing extension points and preserve StatePanel behavior; no parallel dispatch/compiler route.
- Source completeness is explicit: source max timestamps never establish “never treated”; observation exit is distinct from membership exit.
- Separate treatment initiation from persistent-adoption state. Do not imply exposure or treatment merely from EventAnchor or observational occurrence.
- Causal per-trial AIPW requires a named target population, trial aggregation weights, trial-level target weights, complete outcomes, and unit-cluster inference. No automatic dropping, trimming, clipping, imputation, or control substitution.
- Stacked comparisons require roster-backed contemporaneous data, both observation times admissible, and unconditional parallel untreated trends under the actual normalized group weights. Already-treated and anticipation-contaminated units are never controls. Cohort-time effects, anticipation periods, and reference periods are explicit; conflicting references refuse without shifting. Naive staggered TWFE is labeled/warned, never silently presented as robust.
- Matched-t0 sampling retains exact inclusion probabilities, but sampled analysis populations are refused by both panel AIPW and stacked DiD until sampling-aware identification/inference is specified. This is distinct from nuisance-training subsampling.
- Pretrend, placebo, and negative-control diagnostics are evidence with explicit power limitations. Insignificant pretrends do not establish parallel trends or authorize identification.
- Callaway–Sant'Anna adoption/vendorization, licensing/release, landmark causal analyses, and clone–censor–weighting causal grace analyses are owner gates and excluded from this plan. Descriptive initiation frames remain permitted; no causal grace-period claim ships without owner-selected identification design.
- Tests remain xdist-independent and consumer-visible, assert stable codes and numerical contracts, and use slow/parameter_recovery markers plus a small ordinary-suite smoke for calibration work.

## Review Focus

1. Duplicate unit-trial rows leak across nuisance folds or understate uncertainty: Task 3 pins one unit fold across all trials and sums score contributions before the cluster sandwich.
2. A later adoption is mislabeled baseline initiation or treated as persistent exposure: Task 1 pins separate initiation/state encodings; Task 4 pins post-treatment control refusal.
3. Trial weights silently change the target or count overlapping trials multiple times: Task 2 and Task 3 pin per-trial normalization, aggregation weights, scale invariance, and duplicate-trial behavior.
4. Event-time controls include already-treated units or anticipation periods: Task 4 pins at-risk eligibility and coded refusals at the consumer boundary.
5. A null pretrend/placebo result is presented as proof: Task 5 pins joint tests, placebo examples, low-power/unavailable status, and user-facing interpretation.

### Exact interfaces produced by this plan

1. `Design(unit: str, anchor: FixedDate | EventAnchor | Schedule, *, features: Mapping[str, Expr] | None = None, outcomes: Mapping[str, Expr] | None = None, eligibility: Mapping[str, Predicate] | None = None, treatment: Treatment | None = None, gap: str | int = "0d", shape: Literal["cross_section"] | StatePanel | SequentialSpec | EventPanelSpec | CalendarComparisonSpec = "cross_section", anchor_range: AnchorRange | None = None, sample: MatchedT0Sample | None = None)`. Extend existing Design union `"cross_section" | StatePanel`; keep all common inputs here. Shape payloads own only shape-specific decisions.
2. `Initiation(source: str, property: str, *, history_start: datetime, knowledge: Literal["recorded_at","retrospective_effective_time"])` and `PersistentAdoption(source: str, property: str, *, adopted_value: str, history_start: datetime, persistence: Literal["absorbing"], knowledge: ...)` bind to declared sources and complete history. Initiation is classified at exact t0 from known-at-t0 information; persistent state requires explicit absorbing semantics. Refuse later control initiation for sustained no-initiation strategies requiring unsupported censoring/longitudinal adjustment.
3. `SequentialSpec(treatment: Initiation | PersistentAdoption, trial_weight: TrialWeight | None, anticipation_seconds: int, reference_period_seconds: int)` and `Sequential(base: Design, *, treatment: Initiation | PersistentAdoption, trial_weight: TrialWeight | None = None, anticipation: str = "0d", reference_period: str = "-1d") -> Design` define and lower the sequential shape. `CalendarPanel(sequential: Design) -> Design` returns its exact canonical equivalent. Base Design carries unit, anchor, named expressions, gap and range; no common inputs are duplicated. Reject conflict with existing `Design.treatment` before hash/validate/compile.
4. `EventPanelSpec(periods: tuple[int,...], period_seconds: int, reference_period: int)` and `EventPanel(base: Design, *, periods: tuple[int,...], period_seconds: int, reference_period: int = -1) -> Design` lower EventAnchor base Designs. Row k has evaluation origin `event_t0+k*period_seconds`; translate each named expression's declared windows relative to that origin, without forcing one-period outcome windows. Keep expression-relative outcome starts nonnegative as current validation requires; negative event-time period k remains valid. Apply feature/eligibility gap at each evaluation origin. Retain exact parent event timestamp separately, and record row evaluation t0, translated windows/cutoffs in metadata. Use typed `anchor_id=(parent_event_id,k)` to keep `(unit,anchor_id)` unique.
5. `TrialWeight(kind: Literal["equal_trial","explicit"], values: Mapping[str,float] | None = None)` defines positive normalized trial masses `lambda_t`; q_it is unit weight or explicit non-treatment-dependent target weight. With trial-specific nuisances `m_at(x)=E[Y|W=a,X,trial=t]`, `e_t(x)=P(W=1|X,trial=t)`, define `psi_it=m_1t-m_0t + W_it*(Y_it-m_1t)/e_t +(1-W_it)*(Y_it-m_0t)/(1-e_t)` and `ATE_t=sum_i(q_it*psi_it)/sum_i(q_it)`. The target is `sum_t lambda_t*ATE_t`, not raw row pooling.
6. `MatchedT0Sample(strata: tuple[str,...], *, controls_per_treated: int, seed: int)` is serialized in `Design.sample`, included in canonical hash, and consumed on recompilation. Per t0/stratum, retain all treated and sample exactly `controls_per_treated*n_treated` eligible controls without replacement; refuse insufficient controls; retain treated inclusion probability 1 and control probability `n_sampled_controls/n_eligible_controls`.
7. `panel_aipw(frame: MaterializedFrame, *, outcome: str, treatment: str, trial: str, target_weight: str | None = None, folds: int = 5, seed: int = 0, alpha: float = 0.05, nuisance: NuisanceSpec | None = None) -> Estimate`. Trial aggregation weights are read only from canonical panel provenance; never accept a second `trial_weights` argument. Return `trial_weighted_ATE`, `n` trial rows, `n_clusters` units, and `unit_cluster_crossfit_sandwich`; refuse every sampled analysis population.
8. `CalendarComparisonSpec(cohort: Initiation, control: Literal["never_treated","not_yet_treated"], reference_period: int, comparison_periods: tuple[int,...], anticipation_periods: tuple[int,...])` is canonical serialized `Design.shape`, including comparison/history settings in hash. `CalendarComparisonPanel(base: Design, model: Model, *, cohort: Initiation, control: Literal["never_treated","not_yet_treated"], reference_period: int, comparison_periods: tuple[int,...], anticipation_periods: tuple[int,...] = ()) -> Frame` derives a canonical Design and Frame; stored Design recompiles via Frame/dispatch. It rejects `base.sample is not None`. Produce roster-backed adopter and never-adopter rows keyed by `(unit,focal_cohort,calendar_period)`.
9. `stacked_event_study(frame: MaterializedFrame, *, outcome: str, treatment: str, cohort: str, period: str, cohort_weights: Mapping[str,float] | None = None, unit_weight: str | None = None, alpha: float = 0.05) -> StackedEventStudy`. Read control mode, reference period, and anticipation leads only from serialized CalendarComparisonSpec/Provenance; do not accept duplicated overrides. Estimate the q-normalized weighted `ATT(g,t)=mu_g-mu_c` of `D_i=Y_it-Y_ir`, `r=g+reference_period`, q=1 by default. Require unconditional parallel untreated outcome trends between these actual normalized groups, plus consistency, no interference, no anticipation, complete history/outcomes and positivity. Conflicting reference/anticipation specs were rejected at construction; sampled analysis populations refuse.
10. For each CATT, define `Q_g=sum_{G_i=g}q_i`, `Q_c=sum_{C_i=1}q_i`, weighted changes `mu_g,mu_c`, and `IF_i(g,t)=1{G_i=g}q_i(D_i-mu_g)/Q_g - 1{C_i=1}q_i(D_i-mu_c)/Q_c`. Sum each independent unit's appearances across stacks/cohorts into its complete contrast vector and use uncorrected asymptotic cluster covariance `V=sum_i(IF_i IF_i.T)`. Pin the normalization and covariance to an independent numerical reference.
11. `matched_t0(base: Design, model: Model, *, sample: MatchedT0Sample) -> Frame` lowers policy into canonical `Design.sample`; sampling never exists only as an external compiler option.

The executable public example is `examples/sequential_trials.py`: construct a base Design with unit, anchor, expressions; lower it with each shape convenience; serialize/load; build/materialize through native `Model.from_catalog`; compare Arrow round-trips and CalendarPanel/Sequential rows.
