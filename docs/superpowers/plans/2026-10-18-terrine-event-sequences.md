# Bounded Event Sequences, Re-Anchoring and Sessions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add deterministic, bounded event-sequence datasets, event-time re-anchoring, sessionization, funnels, and transitions while preserving Terrine's timestamp, observation, budget, and metadata contracts.

**Architecture:** Add a data-only `EventSequence` shape and typed sequence/funnel/session requests to the existing Design serialization and validation paths. Compile raw events through the native bound Catalog and candidate-anchor relations, returning either position rows or Arrow-list sequence values; use the already-existing single shape dispatcher (including Task 6.2's `StatePanel` branch) rather than adding a parallel compiler. Temporal sequence operations retain exact timestamps and stable event identity, carry observation/completeness and conservative time bounds, and enforce finite per-sequence and materialization budgets before exposing output.

**Tech Stack:** Python >=3.13,<3.15 provisional; Ibis with DuckDB reference backend; Arrow; existing native Catalog/Model, Design/Frame, temporal prefix/as-of and execution snapshot APIs; pytest; pandas as a test/reference-only optional dependency.

**Spec:** `docs/superpowers/plans/2026-10-16-terrine-build.md` §Task 11.1 (bounded event sequences, re-anchoring and sessions), `docs/superpowers/plans/2026-10-16-terrine-study-api.md` (Design/anchor/compiler/Frame contracts), `docs/superpowers/plans/2026-10-16-terrine-temporal.md` (event normalization, exact prefix boundaries, observation/readiness/null semantics), `docs/superpowers/plans/2026-10-16-terrine-dataset-workflows.md` (shared budget/metadata and serialization conventions), and `AGENTS.md` (tests, API/refusal, numerical and serialization requirements). The Task 11.1 master-roadmap section is the only companion-level feature specification; no additional sequence companion is referenced there.

## Global Constraints

- Strict `[start,end)` event windows; exact UTC-aware timestamp time zero; never floor event anchors; ties use the configured stable event ID, and when none is configured, equal `(unit,timestamp)` values refuse rather than acquire arbitrary order.
- Event sequences may read raw events, but must not create an unbounded anchor × all-events expansion; require a positive finite per-sequence `max_events`, a caller-supplied positive `Budget.max_rows` and `Budget.max_output_bytes` for expanded exports, and enforce limits before returning any materialized result.
- Do not claim row/output-byte budgets are scan budgets; keep scan cost separate and unknown when not measured. No network or real warehouse in unit tests; live warehouse tests belong under `integration/warehouse_execution/`.
- Preserve per-source declared readiness and independent unit observation bounds. Distinguish an observed empty interval, an unavailable interval, a null predecessor, and a known-null event value with stable reason metadata; never infer completeness from `max(timestamp)` or roster exit.
- Re-anchoring and downstream time windows must propagate conservative lower/upper timestamp bounds. Refuse a chain whose possible event-time support leaks across the requested feature/outcome/gap boundary; never clip a window or substitute a different anchor.
- Position output preserves every eligible candidate anchor with exactly one anchor header; complete sequences also emit one child row per event, while complete-empty and unavailable/incomplete sequences emit only the header (never partial event children). The header has null event ID/time/position, `is_event=False`, and carries event_count/completeness/reason; complete-empty uses count 0/complete true/no reason, unavailable uses count null/complete false/exact reason. Event children have nonnull stable `sequence_position`, event ID/time and `is_event=True`; their event_count is null. Array output also preserves one row per candidate anchor.
- Use coded immutable `TerrineError` refusals and existing source/identity/snapshot contracts. Public constructors are data-only and serialized by `spec/io.py`; no SQL, callables, credentials, runtime handles, generic transformation DSL, or second shape dispatcher.
- Task 6.2 has added `terrine/compile/dispatch.py`; its actual contract is `compile_design(design: Design, model: Model) -> CompiledStudy`, dispatching `StatePanel` to `compile_state_panel` and the default shape to `compile_columns`. Task 11.1 MUST extend this single dispatcher to route `EventSequence` to `compile_event_sequence`, preserving both existing branches. Do not create another dispatcher.
- Follow Task 0.1/AGENTS test restraint: tiny deterministic independent fixtures, no brittle timing assertions, focused selectors at coherent milestones, no test-count quota. Update every affected export, serialization/validation path, example, guide and changelog in the same delivery.
- Do not adopt or vendor Callaway–Sant'Anna or decide licensing/release questions; those remain owner-reserved gates, outside this task.

### Shared interfaces

- **Consumes:** `Design(unit, anchor, *, features=None, outcomes=None, eligibility=None, treatment=None, gap='0d', shape='cross_section', anchor_range=None)`, `compile_anchors(design: Design, model: Model) -> AnchorTable`, normalized event relations, `Readiness.for_fact(source_name) -> BoundCoverage`, and existing `ColumnMeta`, `Roles`, `Provenance`, `Budget`, and `Frame.materialize(budget: Budget | None = None) -> MaterializedFrame`.
- **Produces, sequence specs:** `EventSequence(fact: str, window: Window, *, max_events: int, representation: Literal['positions','arrays']='positions', properties: tuple[str,...]=(), label_property: str | None=None, sessions: SessionSpec | None=None, funnel: FunnelSpec | None=None) -> EventSequence`. Properties are exported in declared order; `label_property`/`FunnelSpec.event_property` may be internal dependencies, not output columns. `max_events` is a positive signed-Int64 per-anchor cap. `SessionSpec(gap: str | int) -> SessionSpec` accepts nonnegative elapsed seconds and splits only when adjacent elapsed gap `> gap`; sessions and funnel attempts are bounded by the enclosing per-anchor `max_events` cap, with no redundant per-session cap. `FunnelSpec(event_property: str, steps: tuple[str,...], within: str | int | None=None)` requires distinct ordered steps and a positive finite `within` when supplied; it starts one attempt per occurrence of step 0. `within` is the exact half-open deadline `[first_step_timestamp, first_step_timestamp + within)` and is never clipped; when absent, the sequence-window end is the deadline. If a finite deadline exceeds the selected sequence-window end, an unmatched attempt is `unavailable` rather than falsely `failed`; a matched sequence can still be `complete`.
- **Produces, event-time selector:** `EventTime(fact: str, window: Window, *, label_property: str | None = None, equals: str | int | float | bool | None = None, occurrence: Literal['first','nth']='first', n: int | None=None, relative_to: EventTime | None = None) -> EventTime`. With neither filter field, it selects occurrences of the named fact; `label_property` and `equals` must either both be supplied or both omitted. A supplied pair filters on that declared event property after checking the scalar value against its declared type. It selects in a strict half-open search window; `relative_to=None` means Design `t0`, otherwise offsets use the referenced EventTime. Include it in `Expr`, feature/outcome mappings, and serialization. Add keyword-only `relative_to: EventTime | None = None` to `MetricAgg` and `AttributeAsOf`. Canonical tagged JSON/YAML recursively encodes references and rejects malformed occurrence/n pairs or unsupported values.
- **Design integration:** `Design.shape: Literal['cross_section'] | StatePanel | EventSequence`; the existing dispatcher and `Design.features`/`outcomes` accept EventTime and downstream `relative_to` expressions. EventSequence designs may not add treatment or unrelated ordinary outcomes; selector-referenced features/outcomes compile through the same Frame relation.
- **Temporal interfaces:** Temporal functions receive normalized parameters only, never `EventSequence`, `FunnelSpec`, `EventTime`, `Design`, or other `terrine.spec` objects. `event_sequence(events: ibis.Table, anchors: ibis.Table, *, window_start: int, window_end: int, max_events: int, representation: Literal['positions','arrays'], properties: tuple[str,...], internal_properties: tuple[str,...], label_property: str | None, unit_column: str, anchor_id_column: str, timestamp_column: str, event_id_column: str, observed_from_column: str | None, observed_until_column: str | None, complete_from: datetime, complete_until: datetime) -> SequenceResult`; `sessionize(events: ibis.Table, *, unit_column: str, anchor_id_column: str, timestamp_column: str, event_id_column: str, gap_seconds: int, max_events: int) -> ibis.Table`; `funnel_progress(events: ibis.Table, *, event_property: str, steps: tuple[str,...], within_seconds: int | None, sequence_end_column: str, unit_column: str, anchor_id_column: str, timestamp_column: str, event_id_column: str) -> ibis.Table`; and `resolve_event_time(events: ibis.Table, *, window_start: int, window_end: int, label_property: str | None, equals: str | int | float | bool | None, occurrence: Literal['first','nth'], n: int | None, relative_to_column: str | None, unit_column: str, anchor_id_column: str, timestamp_column: str, event_id_column: str) -> TimeResult`. Compile adapters unpack specs, resolve Catalog properties and pass only these normalized values.
- Temporal data results: `SequenceResult(table: ibis.Table, roles: Roles, columns: Mapping[str, ColumnMeta], candidate_rows: int | None, expression_timings: Mapping[str, ExpressionTiming])` and `TimeResult(table: ibis.Table, support_seconds: tuple[int,int], selector_dependencies: tuple[str,...], selector_support_seconds: Mapping[str, tuple[int,int]], complete_column: str, reason_column: str)`. `ExpressionTiming(kind: Literal['fixed_t0','event_time'], selector_ref: str | None, relative_offsets: tuple[int,int] | None, support_seconds: tuple[int,int], selector_dependencies: tuple[str,...], selector_support_seconds: Mapping[str, tuple[int,int]], point_time_column: str | None, start_bound_column: str | None, end_bound_column: str | None, strict_cutoff: bool | None)` is portable metadata per output expression and retains each dependency's own support interval. These are temporal contracts; function inputs contain no study AST types.
- **Symbolic support and dependencies:** Every EventTime contributes a separate selector dependency interval as well as the time origin selected by it. A direct selector has base-t0 search support `[window.start,window.end)`; a nested selector adds its offsets to its parent's support and retains every selector's own shifted search interval. Downstream metric support is `[origin.lower + window.start, origin.upper + window.end)`. For `AttributeAsOf(before=b)`, support is `[origin.lower+b, origin.upper+b)` because its strict lookup is `valid_from < cutoff`; equality to the cutoff is excluded. For every feature/eligibility expression, require both measurement support and every selector-dependency upper bound `<= -Design.gap`; outcome measurement support must have lower bound `>= 0`, and its selector dependencies must be recorded independently. Refuse query-free with no clipping. Runtime selected timestamps remain exact UTC instants; unavailable/censored selector values propagate their original null reason, never a support endpoint.
- **Position/array results and metadata:** Position output has one anchor header per `(unit,anchor_id)` and one child per event. Header carries `is_event=False`, null event ID/time/position, `event_count` and anchor-level `sequence_complete`/`sequence_reason`; complete-empty count is 0/complete true/no reason, unavailable count is null/complete false/exact reason. Event children carry `is_event=True`, nonnull zero-based `sequence_position`, event ID/time/selected fields, and null `event_count`. For each selected property, output its nullable value plus a stable reason (`known_null` for a present event with known-null property); incomplete event observation yields no partial children and preserves its source/readiness/coverage reason at the header. Both representations expose bounded session summaries as `sessions: list<struct<session_index,start_timestamp,end_timestamp,event_count>>`, plus `sessions_complete` and `sessions_reason`; position children carry `session_index` and `session_position`. Each event row also carries `previous_event_id`, `previous_timestamp`, and previous sequence position; if `label_property` is selected, expose `transition_from`/`transition_to` labels. The first row has typed null predecessor with reason `missing_predecessor`, indicating no predecessor inside this selected sequence (not a lifetime claim), never a cross-anchor predecessor. Header/array rows contain `funnel_attempts: list<struct<attempt_id,start_timestamp,progress,status,matched_event_ids,matched_timestamps,reason>>`, `funnel_attempts_complete`, and `funnel_attempts_reason`. Attempt identity is `(unit,anchor_id,step0_event_id)`; every step-0 occurrence starts one attempt, including unsuccessful ones. Fully matched attempts are `complete`; attempts whose full deadline was observed but steps were missing are `failed` with progress/matches; when the requested finite deadline extends beyond the sequence window, an unmatched attempt is `unavailable` with its known progress/matches and reason `sequence_window_end_before_deadline`. Incomplete source observation makes the entire sequence unavailable: emit no partial children/attempts, set a null attempts payload and preserve the exact source/readiness/coverage reason at anchor level. Arrays use one row per anchor and typed event list. Row budgets count headers plus children; nested event/session/attempt elements are bounded by `max_events` per anchor, and actual output bytes are also checked. Existing eligibility applies at anchor grain before expansion; known-false anchors/children are excluded and unresolved predicates use Task 4.2 refusal. `SequenceMeta(fact: str, window: Window, max_events: int, representation: Literal['positions','arrays'], properties: tuple[str,...], property_reason_columns: Mapping[str,str], label_property: str | None, session_gap_seconds: int | None, funnel_event_property: str | None, funnel_steps: tuple[str,...], funnel_within_seconds: int | None, event_id_column: str, event_identity_kind: Literal['configured','timestamp'], timestamp_column: str, position_column: str, is_event_column: str, event_count_column: str, sequence_complete_column: str, sequence_reason_column: str, sessions_column: str | None, sessions_complete_column: str | None, sessions_reason_column: str | None, previous_event_id_column: str | None, previous_timestamp_column: str | None, previous_position_column: str | None, transition_from_column: str | None, transition_to_column: str | None, funnel_attempts_column: str | None, funnel_complete_column: str | None, funnel_reason_column: str | None)` records exact request and public schema/field references; `Provenance.expression_timings` records each expression's portable `ExpressionTiming`. Metadata and values survive Arrow restoration.
- **Stable refusals:** `terrine.sequence.invalid_spec`, `.unsupported_shape`, `.reanchor_leak`, `.max_events_exceeded`, and `.incomplete_time_bounds` are owned by the sequence spec/temporal layers. Configured-ID null/duplicate failures and timestamp-fallback ties MUST use the existing `terrine.compile.anchor_integrity` refusal with `check_key` `null_event_id`, `duplicate_event_id`, or `tied_event_timestamps`; factor the checks into shared anchor helpers rather than add a second identity refusal. Reuse `terrine.budget.rows_exceeded`, `.output_bytes_exceeded`, `.scan_unknown`, `.scan_exceeded`. Context contains identifiers/counts/bounds only, never payloads or customer keys/values.

## Open Decisions and Gates

- **Roadmap underspecification—public forms and grains:** Task 11.1 names sequences, re-anchoring, sessions, funnels, and transitions but does not define their output schemas/grains or whether facts alone identify events. Recommendation: use the typed `EventSequence` shape; default EventTime selection to occurrences of its named fact, with an optional paired `(label_property, equals)` filter; position form is one anchor header plus complete event children; array form is one row per anchor with typed event list. Session summaries are keyed by `(unit, anchor_id, session_index)`, event annotations/transitions by `(unit, anchor_id, sequence_position)`, and funnel attempts by `(unit, anchor_id, step0_event_id)`. All nested outputs are bounded by the enclosing positive `max_events` per anchor. Publish exact schemas and anchor/child completeness rules in the existing guide and tests.
- **Observation and null-result distinction:** The roadmap does not state how incomplete event observation interacts with empty sequences and downstream operations. Recommendation: complete-empty means zero events, complete true, no reason; unavailable means null event count/list, complete false, and the exact source/readiness/coverage reason. Never return partial event children, sessions, transitions, or funnel attempts from an incomplete source-observation window; each requested aggregate reports incomplete with the same reason and null payload. Within a complete sequence, unsuccessful attempts whose full deadlines were observed are retained as `failed`, fully matched attempts are `complete`, and an attempt whose finite deadline extends beyond the selected sequence window is `unavailable` with its known progress and reason (not failed).
- **Session threshold and scope:** Equality and each-vs-global grouping are unspecified. Recommendation: split only when adjacent elapsed gap is strictly `> gap`, order simultaneous events by stable event ID, and partition by `(unit,anchor_id)` so overlapping EventAnchor(each) windows remain independent.
- **Funnel deadline/retry:** The roadmap does not define `within` reference time or expiry behavior. Recommendation: each step-0 event starts an attempt with one exact half-open deadline from its timestamp; `within=None` uses sequence-window end. A finite deadline is never clipped to that end; matched attempts can complete from in-window evidence, a full observed horizon with missing steps is failed, and a horizon extending past the selected window yields unavailable progress/reason rather than false failure. Every later step-0 starts another attempt.
- **Re-anchor API and leakage bounds:** Typed selector shape, chaining and as-of support are unspecified. Recommendation: use serializable EventTime/relative_to, keep selector-dependency support separate from measurement support, shift AttributeAsOf support by `before`, and refuse any possible feature/eligibility leakage query-free without clipping or choosing a point. Record exact runtime point/boundary references in `ExpressionTiming`; baseline estimators require explicit fixed-t0 outcome timing and refuse event-origin outcomes until separately supported.
- **Dispatcher integration:** Inspected the actual Task 6.2 `terrine/compile/dispatch.py` in `/Users/kylejcaron/terrine/.worktrees/build`: `compile_design(design: Design, model: Model) -> CompiledStudy` dispatches `StatePanel` to `compile_state_panel` and defaults to `compile_columns`. Add exactly one EventSequence branch there, preserving both; `Frame.__init__` and `Frame.materialize` already use this dispatcher.
- **Event identity and source normalization:** The existing anchor module owns `terrine.compile.anchor_integrity` with `null_event_id` / `duplicate_event_id`; sequence compilation must share this check and explicitly retain configured `Model.event_ids` through event normalization even when the identity field is not a declared fact/property/entity.
- **Owner-reserved gate:** Do not adopt/vendor Callaway–Sant'Anna or decide licensing/release. Keep those questions outside implementation scope and require owner decision before any related work.
